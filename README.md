# ⚽ Pro Striker — 3D Football Player (eFootball-style)

A real-time **3D footballer built entirely in JavaScript + [Three.js](https://threejs.org/)** —
procedurally **modeled, rigged and animated in code**, with game-grade physics.
No imported character meshes, no AI-generated assets: every vertex, the kit, the
skeleton, the gait cycles and the ball physics are generated by the source in this repo,
designed to look and move like a player you'd see in Konami's eFootball / PES.

> The full engineering analysis that drove this build — anatomy, proportions, rig
> design, biomechanics of every animation, materials and physics constants — lives in
> **[DESIGN.md](./DESIGN.md)**.

---

## ▶️ Run it

The game itself needs **no install and no build step** (Three.js is loaded from a CDN via
an `importmap`). ES modules just have to be served over `http://` rather than opened from
`file://`.

```bash
# from the project root — uses only Node's built-in http server
node serve.mjs
# then open  http://localhost:5173
```

Any static server works just as well, e.g. `python3 -m http.server 5173` or the VS Code
*Live Server* extension.

Optional — to run the headless test suite (clip-data integrity + animator stability):

```bash
npm install      # pulls three locally, dev-only
npm test
```

## ✨ What's in here

**Player** — an anatomically proportioned ~1.80 m athlete (≈7.8 head-units): articulated
torso, neck and head with face features, **detailed hands (palm + four fingers + thumb)**,
studded boots, and a full kit (jersey with crest + back number, shorts, turned-over socks).
Built from tapered cylinders and sphere joints for a smooth, seam-free silhouette.

**Rig & animation** — a real forward-kinematics skeleton (pelvis → spine → chest → neck →
head, plus arms and legs) driven by a quaternion animation system with **snapshot
cross-fade blending**. Twelve hand-authored, biomechanically-grounded clips: *idle, walk,
run, sprint, shoot, pass, throw-in, slide tackle, header/jump, fall, turn* and
*celebration*. Locomotion auto-selects by speed and stride-matches the ground to limit foot
sliding; opposite limbs are derived by half-cycle phase-shift + lateral mirror, exactly how
a symmetric gait works.

**Physics** — a kinematic character controller (acceleration, friction, turn-rate, walk vs
sprint caps) and a Size-5 ball with gravity, restitution bounce, rolling/air friction and a
simplified **Magnus curve** from spin. Kicks fire from the *contact phase* of the shoot /
pass / throw-in / header animations; light auto-dribble keeps the ball at the player's feet.

**Graphics** — physically-based materials, **ACES filmic tone mapping**, sRGB output, soft
(PCF) shadows from a stadium sun, a hemisphere/fill lighting rig, a gradient sky with a sun
disc, subtle **bloom**, and soft studio reflections — tuned to read like a Unity/engine
render. The stadium has a striped pitch with **regulation IFAB line markings** baked in,
two goals with nets, a running track and tiered crowd stands.

## 🧍 Loading a real rigged character (glTF)

The built-in player is generated in code, which tops out at a clean *stylized*
look — procedural code can't reach photo-scanned realism. To get an
**engine/AAA-grade footballer**, drop in a real authored model: the game can
load any rigged humanoid **glTF/GLB** and drive it from the same
movement/physics/camera, animating it with the model's own clips.

```
http://localhost:5173/?model=soldier            # bundled demo (rigged human)
http://localhost:5173/?model=xbot               # bundled demo (Mixamo mannequin)
http://localhost:5173/?model=https://…/you.glb  # ANY rigged .glb URL
http://localhost:5173/?model=…&tint=0x12379e    # optional colour tint
```

The model is auto-scaled to ~1.8 m and grounded; clip names are matched fuzzily
(`idle` / `walk` / `run` / `sprint`). Where to get a proper footballer:

- **Blender / Maya** — export your own sculpted, kitted, rigged player as `.glb`.
- **Mixamo** (free) — a rigged character + locomotion clips in the same `.glb`.
- **Ready Player Me** (free, in-browser) — `?model=https://models.readyplayer.me/<id>.glb`.
- **Sketchfab** — many CC0 / CC-BY footballer models; download the `.glb`.

> Note: real eFootball/PES player assets are Konami's proprietary IP and are not
> used here. Bring a model you've made or that is licensed for your use.

## 🗂 Architecture

```
index.html              # importmap (Three.js CDN), HUD, loader
serve.mjs               # zero-dependency static dev server
src/
  main.js               # bootstraps engine, world, player; game loop + HUD wiring
  core/
    Engine.js           # renderer, post-processing (bloom), tone mapping, loop
    FollowCamera.js     # third-person orbit/zoom follow camera
  world/
    Sky.js              # gradient sky dome + sun shader
    Lighting.js         # sun + hemisphere + fill, shadow camera
    Pitch.js            # striped grass, IFAB markings, goals/nets, stands
  player/
    PlayerModel.js      # procedural rigged humanoid (mesh + FK skeleton)
    PlayerKit.js        # PBR materials + baked number/crest decals
    Animator.js         # quaternion clip player with cross-fade blending
    clips.js            # 12 hand-authored animation clips (keyframe data)
    Player.js           # controller: movement, state machine, kick events
  gameplay/
    Ball.js             # ball mesh (12 pentagons) + physics
  input/Input.js        # keyboard + charge-to-shoot
  util/math.js          # easing / interpolation helpers
test/validate.mjs       # headless data + animator stability checks
DESIGN.md               # the deep design & biomechanics analysis
```

## 🔧 Tech notes

- **Three.js r160** via `importmap` — no bundler, no transpile.
- Pure ES modules; everything is procedural (canvas-baked textures, generated geometry).
- Tested headlessly: clip data is range/joint-validated and the animator is proven stable
  (finite, unit quaternions) across all clips and hundreds of random transitions.
